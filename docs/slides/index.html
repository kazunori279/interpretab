Hi. This is Interpretab, a Chrome extension. It listens to whatever a tab is playing and interprets it out loud, and it does your microphone the other way round. There is no server in the middle: the browser holds the connection, and your own API key. Let me just show you.

Architecture
Interpretab · a personal project
Okay, the shape of it. Three pieces you might not have met. Web Audio is the browser's audio graph; it does the capture and the resampling. A WebSocket is a connection that stays open, so either end talks whenever it likes. And the Live API takes audio in and gives you speech back before the sentence has even finished. All of that lives in one offscreen document, because Chrome kills the service worker after thirty seconds idle and the side panel dies when you close it. Three audio contexts, shared by sample rate, because Chrome only gives you about six.
How it integrates with Meet
No extension can register an audio input with the system. One page is another matter.
Interpretab · a personal project
Meet. An extension cannot register itself as a microphone with the operating system. A page can, though. So we inject a script into Meet's own JavaScript world, and it adds a device called Interpretab to the list. When Meet asks for a mic, it gets a synthetic track. The catch is that a page script cannot reach the extension, so a second script ferries the audio across with postMessage.
The hard parts

Right. Three things that actually fought back. None of them is about translation quality. All three are about keeping a long connection honest on somebody else's schedule.
Session lifecycle
A Live session lasts ten minutes. The server warns you at nine, and it means the deadline literally.
Interpretab · a personal project
A Live session lasts about ten minutes. At nine minutes the server warns you, it gives you fifty seconds, and it means it. So the loop opens the next session while the old one is still talking, swaps over on a finished turn or five seconds of quiet, and replays the audio nothing has answered yet. Six handovers an hour. Worst gap in the translated voice was three point six seconds.
Error handling
A browser is never told why a WebSocket upgrade was refused. That is deliberate.
1006, no reason
A bad key, a spent quota and a captive portal all close the same way. Telling the page apart would make it a cross-origin oracle.
So ask over HTTP first
One GET /v1beta/models with the same key, ahead of the capture prompt. 400 is a rejected key; 401 is a key format the API declines to read as one.
1011, mid-session
A quota crossed during a run closes cleanly, carrying 123 bytes of English cut off mid-URL. Ten retries would all connect and all die.
Both shapes came out of running against the real API rather than reasoning about it: tests/quota-close.mjs moves the free-tier limit down to a hundred tokens, so one session crosses it in six seconds. Retrying for ever is a bug when the answer will not change. A spent quota comes back at midnight Pacific, not in four seconds.
Interpretab · a personal project
When a WebSocket upgrade gets refused, the browser is never told why. Bad key, spent quota, hotel wifi: all the same blank close. And that is on purpose, because otherwise the page becomes an oracle. So we ask the same question over HTTP first, where you get a status code. And do not retry a verdict. A spent quota comes back at midnight, not in four seconds.
Remote configuration
Two facts this build cannot own: which Live models exist, and what they cost. A preview gets two weeks' notice.
Interpretab · a personal project
Two facts this build does not own: which Live models exist, and what they cost. A preview gets two weeks' notice, and a store review can take longer than that. So an hourly job asks the API which models still answer, and a daily one hunts for the replacement. When one is really gone it rewrites a small JSON file on Pages, and every installed copy picks it up within six hours. Data, never logic.

Lessons learned
01

Open a real socket early. Two of the three protocol surprises here are in no document.

02

Ask the same question over HTTP. A close code carries no reason; a status code does.

03

Retry a flaky network, not a verdict. A spent quota comes back at midnight, not in four seconds.

04

Keep what belongs to someone else out of the build. Model names and prices move on their schedule.

The one that cost the most: silence is input. End-of-turn is the server's own voice detection, and it detects it in the audio you send. Stop sending when the speaker stops, and the model waits indefinitely.
Interpretab · a personal project
Four things I would tell the next person. Open a real socket early; two of the three protocol surprises here are in no document. When a close code tells you nothing, ask the same thing over HTTP. Retry a flaky network, not a verdict. And keep other people's facts out of your build. The one that cost me the most: silence is input. End of turn is detected in the audio you send.
